# M3 Kickoff — Multi-Agent Development Prompt (Unlisted beta)

Paste this as the first message to the orchestrator agent. It is self-contained.

---

## Mission

Prepare **M3 — Unlisted beta launch** from `STANDALONE-EXTENSION-PLAN.md`. M0–M2 are done: the serverless build passes all automated gates, `dist/yt-topic-radar-v1.0.0.zip` is reproducible and verifies 34/34. M3 itself (Chrome Web Store submission) is **owner-only** — an account, payment, hosted privacy policy, support email, screenshots, and listing approval cannot be automated. Your job is to automate everything up to the submission boundary: a preflight gate, an unaided-tester acceptance run, and the exact submission/tester paperwork.

Read first: `STANDALONE-EXTENSION-PLAN.md` (M3 scope/constraints/DoD + operational items), `docs/M2-kickoff-prompt.md`, `store/*`, `scripts/package-chrome.ts`, `scripts/verify-package.ts`, `tests/standalone-smoke.mjs`.

## Non-negotiables

- Unlisted only. Do not draft anything that implies a public launch; public flip stays a separate owner decision.
- No product changes (`ui/`, `lib/`, `extension/`, manifests, build scripts). M3 is launch prep only.
- Never invent a support email, privacy-policy URL, homepage, screenshots, listing ID, or approval date. Leave `[OWNER: …]` placeholders intact.
- Do not claim the listing is submitted/approved. Report GO/NO-GO with blockers.
- Do not commit `dist/` artifacts; the zip is regenerated by `bun run package:chrome`.

## Lane A — preflight gate

`scripts/preflight-m3.ts` (Bun, no new deps), run as `bun run preflight:m3`:

1. Locate the newest `dist/yt-topic-radar-v*.zip`; fail if missing.
2. Run `bun scripts/verify-package.ts <zip>` and require exit 0.
3. Version consistency: `package.json`, `scripts/manifest.prod.json`, zip contents `manifest.json`.
4. Required files exist: `store/privacy-policy.html`, `store/listing.md`, `store/permissions.md`, `store/data-disclosure.md`, `store/submission-checklist.md`.
5. **Owner blockers**: scan all `store/**` files for `\[OWNER:[^\]]*\]` and list each occurrence with file:line and the text. Any match is a hard blocker for submission.
6. **Screenshots**: require at least one image in `store/screenshots/` (`png|jpg|jpeg|webp`); report the count. Missing = blocker.
7. **Unchecked submission steps**: parse `store/submission-checklist.md` for `- [ ]` items and list them as blockers (so the preflight cannot pass until the owner ticks them).
8. Print a `GO` / `NO-GO` summary: `blockers=N`, one line per blocker, then the next owner action. Exit 1 on any blocker, 0 when clear.

Add `"preflight:m3": "bun scripts/preflight-m3.ts"` to `package.json`; keep every existing script.

## Lane B — submission paperwork

- `store/tester-instructions.md`: an unaided-tester script — install from the unlisted link, open the side panel, paste a Gemini key, add a topic, scan, open a `[MM:SS]` timestamp, export/import a backup, report back. Include what NOT to do (do not share the key, do not report YouTube UI bugs as product bugs) and a short report template (OS, Chrome version, steps failed, console errors).
- `store/submission-checklist.md`: ordered Chrome Web Store steps with exact values pulled from the actual manifest/listing (name, version 1.0.0, category, permission justifications to paste, privacy-policy URL placeholder, data-disclosure answers to paste, unlisted visibility, tester distribution). Every owner action is `- [ ]`; every pre-verified artifact references the command that proves it (`bun run package:chrome`, `bun run verify:package`, `bun run preflight:m3`).
- `store/release-notes-v1.0.0.md`: user-facing notes for the unlisted beta — standalone (no server), BYOK Gemini, unlimited topics, timestamped digests; explicitly not included: Pro, RSS/alarms/notifications, Firefox/Safari/Edge listing; known limits: YouTube/Google API availability, Gemini model fallback latency, key per-device (not synced).

## Lane C — acceptance run

`tests/m3-acceptance.mjs` (Playwright, dependency-free beyond `@playwright/test`): extract the newest `dist/*.zip` into a temp dir (or use `STANDALONE_EXT_DIR`), launch a persistent context with `--load-extension`, and assert:

1. zero page/console errors on load;
2. starter packs render; no request to `localhost:3456`;
3. save a dummy key, reload, key persists in `chrome.storage.local`;
4. `/api/sync` accepts 6 topics (cap off);
5. with `GEMINI_API_KEY` from `.env.local`, `POST /api/scan {maxVideos:3}` returns 200, `1..3` videos, and `/api/state` now contains the digest;
6. the digest UI renders chapter timestamp buttons; clicking one sets `#ytPlayerIframe` src containing `start=`;
7. `/api/backup/export` JSON has no `geminiApiKey`/`isPro`/`entitlements` and includes topics; importing a backup with extra topics keeps them all (no clamp, `topicsCount > 5`);
8. print `PASS`/`FAIL` per check, exit 1 on failure, and write nothing to the repo.

Header comment must say: manual/opt-in (needs network + a real key), not part of `bun test`.
