1. Overview

Topic Digest for YouTube is an independent, unofficial browser extension. It is not affiliated with, endorsed by, or sponsored by YouTube or Google LLC. YouTube is a trademark of Google LLC.

This policy applies to the standalone browser extension. It explains what the extension stores on your device, what it sends over the network, and what it never collects. The extension has no developer-operated backend, no user accounts, and no analytics service.

In short: your topics, pins, and preferences are stored in your browser (and may sync through your own Chrome profile). Your Gemini API key is stored only on this device. Digests, usage counters, and seen-video IDs are stored in this browser's IndexedDB. The extension talks only to YouTube and to Google's Gemini API, using your own API key.

2. Data stored on your device

The extension uses Chrome's storage APIs and the browser's IndexedDB. The table below lists what is stored and where.

3. Data sent off your device

The extension sends network requests only for the actions you start, and only to the following destinations.

  • https://www.youtube.com — to search for videos, open video and transcript data needed for summarization, and (in builds that include the optional RSS feature) to read public channel feeds. The standalone v1 release does not include RSS polling.
  • https://generativelanguage.googleapis.com — to request summaries and synthesis from Google's Gemini API. These requests use the Gemini API key you provide and include the video information and transcript text needed to produce the summary.

There is no developer-operated server in the request path. The developer does not receive your topics, digests, API key, transcripts, or usage data.

4. What we never collect

  • No developer server or relay: the extension does not send data to the developer.
  • No user accounts and no sign-in to the extension.
  • No analytics, telemetry, crash-reporting, or advertising endpoint is wired up.
  • No sale of data, no advertising profiles, and no credit or lending decisions.
  • No collection of your general browsing history. The extension only acts on searches and videos you explicitly choose to scan.
  • Your Gemini API key is never synced through Chrome, never included in backups, and never sent anywhere except Google's Gemini API.

The extension includes an optional “share anonymous usage stats” preference. It is off by default. In the current release it only stores that preference locally; no statistics are transmitted anywhere, because no analytics endpoint exists.

5. Chrome sync note

Data the extension writes to chrome.storage.sync — topics, pinned channels, preferences, and (if a future version enables Pro) the Pro flag — is handled by Chrome's own sync service. If you are signed in to Chrome with sync enabled, that data may be transmitted to and stored in your Google account, subject to Google's terms and privacy policy. It can therefore appear on other devices signed in to the same Chrome profile.

Your Gemini API key is stored with chrome.storage.local instead. It stays on the device where you entered it and is not part of Chrome sync.

6. Retention and deletion

  • Data stays on your device until you delete it or remove the extension.
  • You can delete topics, pinned channels, or digests from the extension interface.
  • Uninstalling the extension removes its local data, including chrome.storage.local and IndexedDB entries.
  • The Chrome sync copy of your topics, pins, and preferences, if any, is governed by your Google account rather than by this device. To remove that copy, manage or clear synced data in your Chrome sync settings or your Google account's data controls.

Because the developer does not receive your data, there is no server-side copy for the developer to delete.

Host: https://www.youtube.com/* Search YouTube and read the public video and transcript data needed for a scan.
Host: https://generativelanguage.googleapis.com/* Send your chosen content to Gemini with your own API key to create summaries.

About the declarativeNetRequest rule

YouTube rejects some requests made from an extension origin. To let the extension use YouTube's own web API, a single static rule sets the Origin, Referer, and Sec-Fetch-* request headers to https://www.youtube.com for requests to ||youtube.com/youtubei/ (XMLHttpRequest only). The rule is narrow: it matches only YouTube's Innertube endpoint, uses no wildcard hosts, and does not modify any other site or request type. Without it, scans fail because YouTube returns an error for the extension's origin.

8. Third parties

The extension contacts YouTube and Google only when you ask it to scan or view content. Those requests are made directly from your browser. The developer is not a party to them and does not receive a copy.

  • YouTube (Google LLC) receives search and content requests for the topics and videos you scan.
  • Google Gemini API (Google LLC) receives the content you choose to summarize, authenticated with your own API key.

Your use of YouTube and Google services is governed by their own terms and privacy policies. The extension is not affiliated with YouTube or Google.
